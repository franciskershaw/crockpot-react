## Low severity (deferred, not urgent)

### 1. No route-based code splitting — every page ships in one eager bundle

**File**: `src/app/AppRoutes.tsx`

Every route element (`LandingPage`, `BrowseRecipesPage`, `MenuScreen`,
`AuthCallback`) is imported eagerly at the top of the file, so the
whole app ships as a single JS chunk regardless of which page a
visitor actually lands on. Adding `motion` (CFE-004, browse-grid
cascade animation) pushed the production build past Vite's 500KB
chunk-size warning (602KB unminified / 193KB gzipped) — `motion` is
only used inside `RecipeGrid.tsx`, reached via `/recipes`, so a
landing-page or auth-only visitor downloads it for no reason.

**Why it matters**: not urgent today — four routes, and the gzipped
payload is still modest on a modern connection. Worth fixing before
more routes and heavier dependencies pile onto one eager bundle, since
both the value of splitting and the size of the eventual diff grow the
longer it's deferred.

**Fix**: `React.lazy()` + a `Suspense` boundary per route (or React
Router v7's native `route.lazy`) in `AppRoutes.tsx`. Discussed and
deliberately deferred at CFE-004 (2026-09-04) rather than folded into
that ticket's diff.
