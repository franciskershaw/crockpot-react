# CFE-015 — Regulars: restock and manage from the shopping list

**Status: ready to build** once `CROC-038` is done. Screenshots:
`../screenshots/regular items/reg1.png`–`reg11.png` (reviewed 2026-10-03);
spec dump mapped to tokens below. Grilled 2026-10-03 together with `crockpot-go`
`CROC-038`, which owns the data shape, the restock rule and the API
(`../crockpot-go/docs/handoffs/CROC-038.md`). "Default items" is renamed
**regulars**.

**Implementation mode**: AI-driven.

## Facts this rests on (checked 2026-10-03)

- The list panel is header (title, `n / m`, Regenerate, close on mobile) →
  `AddExtraItem` → category groups → footer ("Built from N recipes", Clear list)
  (`src/features/shopping-list/components/ShoppingListPanel.tsx`; drawn in
  `../screenshots/your crockpot/yp1.png`).
- On mobile the same panel renders inside a `BottomSheet`, opened by a FAB
  (`ShoppingListSheet.tsx`).
- Adding an item already uses `AddItemSearch` + `AddItemEditor` from
  `features/catalog` (`AddExtraItem.tsx`). Item creation is admin-only.
- Shopping-list mutations invalidate `shoppingListKeys.list()` on success
  (`hooks/useAddShoppingListItem.ts`).
- Regenerate and Clear list wipe every manual row, restocked regulars included.

## Decisions

1. **One Regulars surface, opened from the shopping list panel**, on desktop
   and mobile. It does two jobs: **restock** (main) and **edit regulars**
   (secondary mode, one tap away). Rejected: a fifth Your Crockpot tab (takes
   restock away from the list) and a settings page (`CROC-051`, undesigned).
2. **Two restock gestures.**
   - **Add all**: one tap, sends every regular's ID. No confirmation, since
     the server skips anything already on the list unbought.
   - **Pick**: checkboxes, all pre-ticked except regulars already **on the
     list, unbought** (same item + unit). Those show disabled with "on your
     list". Regulars whose list row is bought are normal options, pre-ticked.
3. **"On your list" is derived on the client** from the cached shopping list,
   matching item + unit (null matches null). The server applies the rule
   anyway, so a stale cache only risks a checkbox that's briefly wrong.
4. **Edit mode** adds regulars with the same `AddItemSearch` + `AddItemEditor`
   as "Add something extra"; items already a regular are marked as such in
   search. Quantity and unit can be changed on an existing regular; a regular
   can be removed.
5. **Empty state**: with no regulars, the surface invites adding the first ones.
   No separate onboarding.
6. **No "star this row as a regular" shortcut** in v1.
7. **After restock**, invalidate the shopping list query. Restocked rows are
   ordinary manual rows.
8. **Errors**: `regular_exists` and `regulars_limit_reached` (cap 50) get
   user-facing copy; the item search shouldn't offer an existing regular in the
   first place.

### Settled at screenshot review (2026-10-03)

9. **Successful restock returns the panel to the list view**, where the new
   rows flash and scroll into view (`reg4`). `reg10`'s "back chevron returns"
   caption is superseded.
10. **Desktop is the source of truth for content.** Mobile restock keeps the
    "Or pick what you need" divider and Add all's refresh icon (missing from
    `reg9` 9B); the mobile list header keeps today's Regenerate and close ×
    (missing from 9A).
11. **Add all carries no count**: "Add all to list". Only the confirm button
    counts ("Add 6 to list").
12. **Zero regulars**: the entry row's trailing text reads "None yet" instead
    of "N saved"; the empty-list copy keeps today's wording unless the user has
    regulars, in which case it's `reg8`'s "Add a recipe, or restock your
    regulars above."
13. Restocked rows render as the real `ShoppingListRow` (quantity pill, delete),
    not the simplified rows drawn in `reg4`/`reg10`. Category labels and unit
    abbreviations come from data (`House`, `rolls`), not the mocks' placeholders.
14. Back from Edit goes to the restock view; back from restock goes to the list.
    The empty state's "Add a regular" opens Edit with the search focused.
15. Undrawn states follow existing patterns: loading uses a skeleton matching the
    restock layout; a failed load or restock shows inline retry copy, as the list does.
16. Implied changes: `AddItemSearch` gains a way to show items disabled with a
    tag ("Already a regular"); the panel's `recentlyAdded` flash handles several
    rows at once.

## Design brief (for Claude Design)

> **Crockpot: "Regulars" for the shopping list**
>
> Crockpot is a recipe and meal-planning app. Its shopping list is built from
> the recipes on your menu, and you can add extra items by hand ("Add
> something extra"). Design a feature called **Regulars**: a personal list of
> things you buy most weeks regardless of what you're cooking (toilet paper,
> milk, bin bags, eggs), each with a quantity and unit (e.g. "Toilet paper ·
> 9 rolls", "Milk · 2 pt"). Before a shop you **restock**: put your regulars on
> the shopping list in one go, or pick the ones you need.
>
> **Where it lives.** Inside the existing shopping list panel: the dark-header
> card on the right of the Menu tab on desktop (see the Menu tab design), and
> the same panel inside a bottom sheet on mobile. Please design the entry point
> into Regulars from that panel (a header button, a row near "Add something
> extra", a footer link — your call) and the surface it opens.
>
> **The hard problem: mobile.** The shopping list is already a bottom sheet.
> Regulars has to open from inside it without a confusing sheet-on-sheet.
> Options worth trying: a view that replaces the list inside the same sheet
> (with a back control), an expanding section within the list, or a
> full-height takeover. Show what you'd pick.
>
> **Behaviour to design for (fixed):**
> - **Add all**: one prominent action that puts every regular on the list.
>   Safe to tap twice; anything already on the list isn't doubled. Needs no
>   confirmation dialog.
> - **Pick**: each regular has a checkbox, all ticked by default. You untick
>   what's still in the cupboard, then confirm ("Add 7 to list" or similar).
> - A regular that's **already on the list and not yet bought** shows as
>   disabled with an "on your list" label. It can't be picked.
> - **Edit regulars**: a secondary mode reached from the same surface. Add
>   a regular with the same search box + quantity/unit editor used for "Add
>   something extra"; change a regular's quantity/unit; remove one.
> - Regulars are grouped by the same categories as the shopping list
>   (Fruit & veg, Dairy, House, …).
> - A limit of 50 regulars exists but should rarely surface.
>
> **States to mock (desktop panel and mobile, unless noted):**
> 1. Entry point on the shopping list panel (populated list).
> 2. Regulars, restock view, ~8 regulars across 3 categories, two of them
>    "on your list".
> 3. Same view with a few unticked and the confirm button's count updated.
> 4. Shopping list right after a restock (how newly added rows are shown;
>    the list already has a brief row-highlight flash for manual adds).
> 5. Edit mode: list of regulars with quantity/unit editing and remove.
> 6. Edit mode: adding a regular via search (an item that's already a regular
>    shown as such in the results).
> 7. Empty state: no regulars yet, inviting you to add some.
> 8. Empty shopping list with regulars available (e.g. right after "Clear
>    list" or "Regenerate", which both remove restocked items) — is restock
>    offered here?
> 9. Mobile only: the full flow inside the bottom sheet (entry → restock →
>    back to the list).
>
> **Constraints:** match the existing shopping list panel exactly (Newsreader
> display headings, Karla body, cream card on beige, dark header bar, green
> primary, rust for destructive). Reuse its row anatomy (checkbox, name,
> `× quantity` pill, unit) where it fits. No new colours. Must work at 375 px
> wide. Out of scope: a "star as regular" action on list rows, reordering
> regulars, anything outside the shopping list panel.

## Acceptance criteria

Behavioural (fixed now):

- [ ] Regulars open from the shopping list panel on desktop and in the mobile sheet.
- [ ] Add all sends every regular's ID to `POST /shopping-list/restock`; the list refetches.
- [ ] Pick pre-ticks every regular except those on the list unbought (item + unit,
      null matches null), which are disabled; the confirm button sends only ticked IDs
      and is disabled with none ticked.
- [ ] A regular whose list row is bought is pickable and pre-ticked.
- [ ] Edit mode creates, edits quantity/unit and removes regulars; search marks existing regulars.
- [ ] Empty state shown with no regulars.
- [ ] `regular_exists` / `regulars_limit_reached` / load and restock failures show copy, not a blank.

Visual (from `../screenshots/regular items/`; get the Claude Design spec dump
before writing markup, per `CLAUDE.md` design-artifact grounding):

- [ ] `reg1` / `reg8`: an entry row directly below "Add something extra":
      round icon tile with a refresh glyph, "Regulars", muted "N saved"
      ("None yet" at zero), chevron. Present whether the list is full or empty.
- [ ] `reg8`: empty list with regulars shows "Your list is empty. Add a recipe,
      or restock your regulars above." centred below the entry row.
- [ ] `reg2`: restock view inside the same panel: dark header with back
      chevron, "Regulars" title, outlined "Edit" pill (pencil icon) on the right;
      full-width filled green "Add all to list" with refresh icon; centred
      "OR PICK WHAT YOU NEED" divider; uppercase muted category labels with a
      rule beneath (no counts, not collapsible); rows of checkbox + name +
      muted "× qty unit"; outlined full-width "Add N to list" in a footer
      replacing the list footer; body scrolls between the two buttons.
- [ ] `reg2`: an on-list-unbought row is dimmed with a disabled checkbox and a
      pill tag "On your list" on the right.
- [ ] `reg3`: unticking updates the confirm count live; at zero it greys out
      (border `border`, text `separator-muted`) and does nothing.
- [ ] `reg4`: after restock the list shows the new rows highlighted
      (`#E6ECDD` flash, fades), their categories expanded, header count updated.
- [ ] `reg5`: Edit view: header with back chevron and "Edit regulars", no
      right-side action; "Add a regular" search input; category labels as in
      restock; rows of name + qty/unit chip + rust trash icon; the open chip is
      the existing × / qty / unit / ✓ editor; no footer.
- [ ] `reg6`: search results mark an existing regular dimmed with
      "✓ Already a regular" and it can't be picked; other results show their
      category on the right.
- [ ] `reg7`: zero regulars: centred round refresh icon tile, "No regulars
      yet" in the display font, explanatory copy, filled green "+ Add a regular".
- [ ] `reg9`: on mobile the same three views swap inside the existing bottom
      sheet, with no second sheet; restock footer button pinned at the sheet's bottom.

## Non-goals

- Star-as-regular from list rows; reordering; a settings page or new tab.
- Showing regulars anywhere outside the shopping list panel.

## Verification

- **Logic**: Vitest for the "on your list" derivation (absent, unbought,
  bought, null unit, different unit) and the restock/regulars hooks
  (`npm test -- regulars` or the feature path).
- **Visual**: founder compares the running panel against each screenshot in
  `../screenshots/regular items/`, desktop and mobile. No screenshot for a state
  means blocked, not guessed.
- **Interactive**: founder uses Add all, Pick, and Edit by hand against the
  local `crockpot-go`, including tapping Add all twice and restocking after
  ticking a row off.

## Build shape

- Three content states in `ShoppingListPanel` (list / restock / edit), swapped
  on local state; header title, back chevron and right-side action follow the
  state (`reg11` build notes). No new route or modal.
- Folder placement (`shopping-list/` vs a new `regulars/` feature) is decided
  at build time by the feature-folder rules in `CLAUDE.md`.
- Piece order: data/hooks + the "on your list" derivation (test-first) → entry
  row + restock view's thin slice with empty state → restock actions + return
  and flash → edit mode.
