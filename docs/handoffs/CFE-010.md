# CFE-010 — Manual recipe form (create + edit)

The "fill it in yourself" half of `screenshots/add recipe/` (`add1`–`add9`):
create at `/recipes/new`, edit at `/recipes/:id/edit`, with a
browser-only autosaved draft and a leave-with-unsaved-changes prompt.
Grilled 2026-09-28; amended 2026-09-30 against the redesigned
screenshots (ingredients, instructions and categories changed). Depth:
mostly cheap to undo (a screen), except the form's value shape, which
`CFE-011` (ingredient paste), `CFE-013` (link import) and `crockpot-go`
`CROC-039` ("New" items) will all fill. AI-driven; founder reviews on
screen at each piece.

## Facts checked before deciding

- Request body (`crockpot-go/internal/handler/recipe_requests.go:13-34`):
  `name` 3–100, `description` optional ≤500, `timeInMinutes` 1–1440,
  `serves` 1–50 (`validation.go:67`), `instructions` 1–50 non-blank,
  `notes` `string[]` ≤10 (blanks dropped), `categoryIds` 1–3 no dupes,
  `ingredients` 1–50, no duplicate item, quantity > 0, unit optional,
  `image` optional and `https://res.cloudinary.com` only (`:329`).
  `PATCH /recipes/:id` is a full replace with the same body (`CROC-016`).
- Units (`crockpot-go/internal/repository/recipe.go:522-532`): no unit is
  always accepted; a unit must be in the item's allowed set when that set
  is non-empty; an empty set accepts any unit. Quantity column is
  `NUMERIC(10, 2)`; `shopping-list/utils/quantity.ts` already holds the
  6-digit/2-decimal input rule (`CFE-042`).
- Items have no default unit: `Item` is `{ id, name, categoryId,
  allowedUnitIds }` (`catalog/data/types.ts:1`), and allowed units come
  back `ORDER BY unit_id` (`crockpot-go/internal/sqlc/queries/items.sql:8`),
  i.e. arbitrary. Legacy data: 335 of 387 items have 2+ allowed units.
- `HydratedIngredient` (`recipes/data/types.ts:58`) carries
  `itemCategoryName`; `CategoryIcon` (`catalog/components/CategoryIcon.tsx`)
  maps a category name to its icon, as the detail page does
  (`recipes-detail/components/IngredientsSection.tsx:65`).
- `AddItemSearch` (cmdk, `shopping-list/components/AddItemSearch.tsx`)
  renders the category *name* on the right of each result and takes an
  optional `onCreate`. `add4` wants the category *icon* on the left and a
  `+` on the right. No stepper component exists yet.
- Shopping-list quantity editing: `AddItemEditor` is the add-time pill
  (✕ | quantity input | unit `Select` starting on "No unit" | ✓, Enter/Esc)
  that replaces the search box once an item is picked
  (`AddExtraItem.tsx:60`); `QuantityControl` is the resting number that
  opens an animated ✕ | input | ✓ editor on tap. Both use
  `utils/quantity.ts`. Neither has ± buttons. `AddExtraItem.tsx:40-44`
  passes only the item's allowed units, so an item with none offers only
  "No unit" there.
- Household items: the "House" item category (29 legacy items — toilet
  paper, bin bags, dishwasher tablets…); no migrated recipe uses one.
  `GET /items` takes no params (`crockpot-go/internal/handler/item_handler.go:40`);
  `useItems` is one cached catalogue fetch shared by browse
  (`BrowseRecipesPage.tsx:43`, feeding `IngredientFilter`), the shopping
  list and this form.
- Migrated instructions (`crockpotV3.Recipe.json`): 1006 steps across 213
  recipes, none containing a newline, none starting with numbering, max
  12 per recipe — so one-line-per-step round-trips losslessly.
- `POST /items` is admin-only (`crockpot-go/main.go:160`);
  `AddExtraItem.tsx:34` gates `CreateItemDialog` on `role === "ADMIN"`.
- `react-hook-form`, `@hookform/resolvers` and `zod` are already
  dependencies.
- `AddRecipeLink` is an inert `<span>`; `RecipeEditButton` already links
  to `/recipes/:id/edit`, which has no route.
- Old app notes: one note per textarea line (`recipe-form-helpers.ts`
  `transformTextareaToNotes`, joined with `\n`).
- `canManageRecipe` (`recipes/hooks/useRecipePermissions.ts:7`): ADMIN or
  creator. `useDeleteRecipe.ts:31-38` is the list/favourites cache
  precedent.

## Decisions

1. **Drafts are browser-only.** One `localStorage` draft for the create
   form, autosaved as you type, restored on return to `/recipes/new`,
   cleared on successful create. "Draft saved" indicator stays; the
   "Save as draft" button is dropped even though `add7`/`add9` draw it
   (no distinct job once autosave exists, and it would imply a server
   save). Edit mode does not autosave. Rejected: server drafts (schema
   change, relaxed validation, cap/`mine`/approval ripple for two admin
   users). Revisit if cross-device drafts are asked for.
2. **Leave prompt via a data router** — done in `e74c632`. The form
   blocks with `useBlocker` (in-app links, back/forward, iOS swipe-back)
   and `beforeunload` (reload/close), only while dirty and never after a
   successful save; the dialog is `ConfirmActionDialog`. Known limits:
   iOS plays the swipe animation before the block restores the page;
   swiping out of the site from a first-in-history edit page can't be
   blocked (create is covered by the draft).
3. **Form value shape** — one `RecipeFormValues` (react-hook-form + Zod)
   with `fromDetail` (`RecipeDetail` → values) and `toRequest` (values →
   body). Paste and import will produce `RecipeFormValues` into the same
   form.
   ```ts
   type IngredientRow = { key: string; itemId: string; itemName: string;
                          itemCategoryName: string;
                          unitId: string | null; quantity: string };
   type RecipeFormValues = {
     name: string; image: { url: string; filename: string } | null;
     description: string | null; timeInMinutes: number; serves: number;
     categoryIds: string[]; ingredients: IngredientRow[];
     instructions: string; notes: string;
   };
   ```
   `itemId` is required: nothing in this ticket produces an unmatched
   row, and widening it for `CROC-039` is compiler-guided. `quantity`
   stays a string until `toRequest`, parsed with the shopping-list rule,
   which moves to shared `lib/` (second caller). `instructions` is the
   textarea's raw text; `toRequest` splits it (decision 9) and
   `fromDetail` joins steps with `\n`.
4. **Units.** Adding an item starts on "No unit", always; the user picks.
   The search dropdown shows no unit hint (`add4`'s is a design mistake).
   Options offered = the item's allowed set if non-empty, else all units,
   plus "No unit". Mirrors the backend so `unit_not_allowed_for_item` is
   unreachable. Rejected: a backend default unit per item.
5. **Duplicates**: picking an already-listed item opens that row's
   editor instead of adding one. Rejected: merging quantities (silently
   changes a value).
6. **Notes**: one textarea, one note per non-blank line (the old app's
   rule, lossless for migrated data); edit joins with `\n`. More than 10
   non-blank lines is a form error.
7. **Description**: not in the design, not in the form. Carried through
   `fromDetail` → `toRequest` unchanged so `PATCH` doesn't wipe it.
8. **No reordering** of ingredients or steps. New ingredient rows append
   (`add5`).
9. **Instructions** (`add2`, `add3`, `add9`): one textarea, one step per
   line, with an Edit ↔ "Preview steps" toggle. Preview is read-only
   numbered cards of the parsed steps. Parsing (`parseSteps`): split on
   newlines, trim, strip leading numbering ("1.", "1)", "Step 1:"), drop
   blank lines. Opens in Preview when there are steps on load (edit,
   restored draft), Edit otherwise. Fewer than 1 or more than 50 parsed
   steps is a form error. Hint text per `add2`.
10. **Ingredients section** (`add1`, `add4`, `add5`): heading with count
    badge and the "Search our list first…" subtitle; search input shown
    directly; results show category icon, name and `+` (no unit hint).
    `AddItemSearch` gains a presentation option for this layout rather
    than a second search implementation; the shopping list's look is
    unchanged. No Manual/Paste toggle until `CFE-011`. Admins get "Add
    'X' as a new item" via `CreateItemDialog`, as the shopping list does
    (undesigned here; reuse as-is). Rows: quantity + unit (decision 14),
    item name, category icon, trash. Empty state: "No ingredients yet —
    search our list above." No matched dots or "New" badges (`CROC-039`).
11. **Routes**: `/recipes/new` and `/recipes/:id/edit`, both under
    `RequireAuth`, lazy. `AddRecipeLink` becomes a `<Link>` to
    `/recipes/new`. Edit loads via `getRecipe`/`recipeKeys.detail`; if
    `canManageRecipe` is false, redirect to `/recipes/:id`.
12. **After save**: `navigate("/recipes/:id", { replace: true })`; seed
    `recipeKeys.detail` with the response; invalidate `recipeKeys.lists()`
    and `recipeKeys.favourites()`; on edit also invalidate the menu and
    shopping list. Non-admin create: toast "Submitted — only you can see
    it until it's approved." Non-admin editing an approved recipe: footer
    note "Saving sends this back for approval." `409
    recipe_limit_reached`: footer error, draft kept. No pre-flight cap
    check.
13. **Validation**: Zod mirrors the backend limits above. Footer shows
    live status — the missing items in `add7`'s wording, or `add9`'s
    "Looks complete — ready to publish". Publish is never disabled;
    submitting with gaps shows inline errors (first attempt onward) and
    focuses the first. Any server 400 shows as one generic footer error.
    Labels: "Publish recipe" (create), "Save changes" (edit).
14. **Steppers and quantity**: time defaults 30, ±5, clamped 1–1440, typeable; serves
    defaults 4, ±1, 1–50. **Ingredient quantity has no ± buttons** —
    it feels like the shopping list, reusing its components (moved out of
    `shopping-list/` on this second caller):
    - *Adding*: picking an item swaps the search box for `AddItemEditor`
      (name × [✕ | 1 | unit | ✓]). ✓/Enter appends the row and returns to
      the search; ✕/Esc adds nothing. Form values only ever hold
      confirmed rows.
    - *Editing*: a row rests as the quantity pill and unit abbreviation;
      tapping the number opens `QuantityControl`'s animated editor with
      the unit `Select` added between input and ✓. ✕/Esc reverts both.
    - The recipe form passes its own unit options (decision 4); the
      shopping list's behaviour is unchanged.
15. **Photo**: omitted on create until `crockpot-go` `CROC-040`. On edit
    an existing image shows read-only and is sent back unchanged.
16. **Undesigned states**: edit mode reuses the create layout titled
    "Edit recipe" with no import card; field errors use the existing
    destructive text style under each section; leave prompt is
    `ConfirmActionDialog` as-is; the revealed chef's notes card (no
    screenshot since the redesign) follows the details card's styling
    with a trash to remove it. Mobile per `add8`/`add9`: back-arrow
    header (goes through the leave prompt), single column, footer
    stacked.
17. **Categories** (`add6`): selected categories as green chips with ×,
    plus a dashed "+ Add category" chip opening a checklist popover of
    the real categories. At 3 selected, unchecked options disable and the
    popover's footer reads "Up to 3 — remove one to add another"; "Done"
    closes it.
18. **Ingredients only.** The form's search excludes items whose
    category is flagged as not an ingredient (House). The flag comes from
    `crockpot-go` `CROC-061` (a boolean on item categories, exposed by
    `GET /item-categories`; recipe create/update rejects such items), and
    the form filters the shared cached `useItems` list by it — no second
    fetch. Rejected: a `GET /items` param (a second cache entry, and the
    API would still accept House items); matching the name "House" in the
    client (breaks silently on a rename). Browse's `IngredientFilter`
    gets the same exclusion in `CFE-047`.

- [ ] Header, mobile tab bar and My recipes empty state link to
      `/recipes/new`; `RecipeEditButton` reaches a working edit page.
- [ ] A non-owner, non-admin hitting `/recipes/:id/edit` lands on
      `/recipes/:id`.
- [ ] Instructions parse and preview per decision 9.
- [ ] Unit defaults and options, quantity editing, duplicate handling,
      admin item creation and the ingredients-only search per decisions
      4, 5, 10, 14, 18; the shopping list behaves exactly as before.
- [ ] Category cap per decision 17.
- [ ] Footer status and submit-time errors per decision 13.
- [ ] Create saves against the real API, lands on the detail page with
      no spinner, and appears in My recipes; non-admin sees the pending
      toast.
- [ ] Editing a migrated recipe preserves its image, description, every
      step and every note line; menu and shopping list refresh.
- [ ] Create draft survives a reload and clears after a successful save.
- [ ] Dirty form prompts on in-app navigation, back/swipe-back and
      reload; clean or just-saved form never prompts.
- [ ] `npm run build` chunk check: the form's deps stay out of the eager
      bundle (`LESSONS.md` 2026-09-27).

## How pieces are cut

- One commit per piece; stop at each for the founder's look and a
  commit message. At the start of each piece, name the files it will
  touch.
- A component that doesn't exist yet gets its own piece: built in place
  on `/recipes/new` with local state and real API data, approved on
  screen, committed — before it is wired to the form. Wiring and logic
  come in later pieces.
- No piece bundles two new visual components.
- Styling comes from the Claude-Design spec dump of the redesigned
  screens, which the founder supplies at piece 2 — no markup before it.

## Non-goals

- Photo upload (`crockpot-go` `CROC-040`).
- Ingredient paste / Manual–Paste toggle (`CFE-011`) and link import
  (`CFE-013`).
- Unmatched/"New" ingredient rows (`crockpot-go` `CROC-039`).
- A default unit per item.
- Server-side drafts; edit-mode autosave; a "Save as draft" button.
- Reordering ingredients or steps.
- A description field.
