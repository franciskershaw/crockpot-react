# CFE-006 — Menu tab + shopping list (absorbs former CFE-009)

Grilled 2026-09-23, against `screenshots/your crockpot/yp1.png`, `yp3.png`,
`yp5.png`, `yp7.png`, `yp8.png`, `yp9.png`, `yp10.png` (all updated/new that
day) plus `yp2.png`/`yp4.png`/`yp6.png` (unchanged since 2026-08-11, referenced
for cross-tab consistency only).

**Summary**: Menu tab (desktop + mobile) ships with the shopping list fully
interactive and inline, not as a read-only summary pointing at a separate
ticket. `CFE-009` is retired as a result. A new mobile-only interaction
pattern (tap-to-overlay quantity edit + remove + undo) is introduced and
also governs `CFE-007`/`CFE-008`'s mobile rows once they're built.

## Decisions

1. **`CFE-009` retired, folded into `CFE-006`.** `yp1.png` draws the shopping
   list as fully interactive (checkboxes, per-item delete, inline quantity
   edit, add-extra, clear-list) sitting directly on the Menu tab, not the
   read-only summary the backlog previously split across two tickets. One
   ticket builds both since the design treats them as one screen.

2. **Regenerate button blocks this ticket on new backend work.** `yp1.png`
   draws a "Regenerate" button, but `crockpot-go`'s shopping list only
   regenerates as a transactional side effect of menu writes (`CROC-021`) —
   there's no endpoint a manual button could call. Dug into the actual
   dismissal mechanism (`CROC-021.md:168-197`, `CROC-022.md:134-143`): a
   deleted item's dismissal is sticky *only* while the quantity it needs
   stays exactly the same — any menu change that alters the needed quantity
   auto-reverts the dismissal already. What's missing is a way to clear
   dismissals **without** a menu change (the actual "get my deleted items
   back" use case). Filed as new backend ticket `CROC-052`
   (`DELETE /shopping-list/dismissals`-shaped) in `crockpot-go`'s backlog.
   **`CFE-006` is blocked on `CROC-052` landing** before it ships — not a
   ship-without-the-button-then-add-later split; the founder chose to block
   rather than ship a known-incomplete affordance.

3. **Quantity editing is open on every row, including recipe-driven ones,
   exactly as drawn** (`yp1.png`'s "Red peppers" in-progress editor). The
   backend already allows `PATCH` on any row but doesn't protect a
   recipe-driven row's edit from the next regeneration (`CROC-022` decision
   3, an accepted backend tradeoff). Decided: no extra UI warning about that
   transience — ship it as designed.

4. **Progress indicator is plain text, no visual bar.** `yp1.png` shows
   "10 / 27" next to the header with no bar graphic (the old design's
   progress bar is dropped). Confirmed final, not an oversight.

5. **Add-extra ports the old app's behaviour, not its code.** Old app
   reference: `crockpot/src/app/your-crockpot/components/Menu/{ShoppingList,
   AddItemEditor}.tsx` + `src/components/dialogs/ItemDialog.tsx` — a
   typeahead search (`Searchable`) over the item catalog, with an
   admin-only "Add new item" that opens a create-item dialog and
   auto-selects the result into the same quantity/unit confirm control.
   Buildable against today's API with no new backend work: `CROC-012`
   (Items CRUD, admin-only writes, public reads) already ships
   `GET`/`POST /items`. **Port behaviour, not code** — this is founder's own
   prior "vibe coded" app; if a needed shadcn primitive (combobox/command,
   dialog) isn't already generated into this project, install it via the
   shadcn CLI rather than hand-rolling an equivalent.

6. **New mobile row pattern for Menu (and, later, Favourites/My Recipes):
   compact list-row + cart-icon-with-badge trigger + full-row overlay edit +
   undo banner.** Per `yp8`/`yp9`/`yp10`:
   - Default row (`yp8`): small thumbnail, title, time, heart (favourite),
     and the recipe's already-in-menu serves count shown via the **existing
     shipped cart-icon-with-badge** component (the same one used on
     Browse/Favourites `RecipeCard`s) — not a new icon. The row layout
     itself is the compact list style, not the full photo `RecipeCard`;
     the cart-icon was only cross-referenced to show where the badge-count
     idea already exists.
   - Tapping the trigger (`yp9`) overlays the **entire row** (not a small
     popover) with a cancel(✕) / stepper(−, count, +) / confirm(✓) control,
     plus a full-width red "Remove from menu" button underneath. The rest
     of the row's content is covered while this is open.
   - Confirming removal (`yp10`) replaces that row with an inline
     "Removed [title] — Undo" banner in the list (not a floating toast),
     which **auto-dismisses after a few seconds**. Undo works by silently
     re-calling the add-to-menu endpoint with the cached recipe + serves —
     a real round-trip (removal already committed server-side and
     regenerated the shopping list), not a true client-side undo.
   - **This pattern is mobile-only and permanent** — not a placeholder.
     Desktop keeps the existing shipped `RecipeCard` cart+stepper
     interaction (`CFE-020`) completely unchanged; no "Remove from menu"
     wording or Undo banner is added to desktop. Applies to Menu,
     Favourites, and My Recipes mobile rows alike (see `CFE-007`/`CFE-008`
     below) — decided as a permanent cross-tab pattern, not scoped to Menu
     only.

7. **Desktop Menu-tab card has no bespoke "×" control.** `yp1.png`'s plain
   corner "×" was a design-tool draft artifact, superseded: desktop reuses
   the existing shared `RecipeCard` exactly as already shipped for
   Browse/Favourites (cart+stepper, heart) — "nothing changes" on desktop.

8. **Mobile "..." overflow (Open planner / Clear menu) is Menu-tab-only.**
   Desktop shows the same two actions as plain inline buttons in the footer
   bar (`yp1.png`); mobile collapses them into the "..." menu (`yp5`/`yp8`)
   for space. Not present on Favourites/My Recipes (no equivalent bulk
   actions there).

9. **Shared empty-state panel pattern, reused across all three tabs.**
   `yp7.png` (Menu, "Nothing on the menu yet") sets the pattern: icon +
   heading + subtext + CTA button. Favourites and My Recipes each get their
   own instance with tab-appropriate copy/CTA (Favourites: "Browse
   recipes"; My Recipes: "Create a recipe", opening the same flow as the
   "+ New recipe" button) — no screenshot exists for either, but the layout
   is a direct reuse of an existing pattern, not new design.

10. **My Recipes' inline "Create a recipe" placeholder tile (`yp4.png`) is
    dropped entirely, desktop and mobile.** The existing "+ New recipe"
    button (top right, desktop) is the only create entry point; the empty
    state's CTA (decision 9) triggers the same flow. This is a real,
    deliberate delta from `yp4.png` as drawn — noted here since it isn't
    obvious from a diff against a screenshot that no longer matches.

## Acceptance criteria

- [ ] Desktop Menu tab matches `yp1.png`: recipe cards are the existing
      shared `RecipeCard` (no bespoke remove control), full shopping list
      inline (categorised, checkboxes, per-item delete, inline quantity
      edit on any row, "10 / X" text count, add-extra, clear-list), footer
      bar with "Open planner" / "Clear menu".
- [ ] Desktop Menu empty state matches `yp7.png`.
- [ ] Mobile Menu tab matches `yp8.png`: compact rows, heart, cart-icon
      badge showing current serves.
- [ ] Tapping the mobile cart-icon trigger overlays the full row per
      `yp9.png` (cancel/stepper/confirm + "Remove from menu"), covering the
      row's other content while open.
- [ ] Confirming "Remove from menu" on mobile shows the "Removed X — Undo"
      banner per `yp10.png`, auto-dismissing after a short timeout; Undo
      re-adds the recipe at its previous serves.
- [ ] Mobile "..." menu (Open planner / Clear menu) present on Menu tab
      only.
- [ ] Add-extra: typeahead search over `GET /items`; admin-only "add new
      item" path creates via `POST /items` and auto-selects the result into
      the quantity/unit confirm control (ported behaviour from
      `crockpot/src/app/your-crockpot/components/Menu/{ShoppingList,
      AddItemEditor}.tsx`, rebuilt against this project's own components —
      generate any missing shadcn primitive via its CLI, don't hand-roll).
- [ ] Quantity edit available on every shopping-list row (manual and
      recipe-driven), no transience warning.
- [ ] Regenerate button **not shipped** until `CROC-052` lands (see
      non-goals) — ticket stays blocked, not partially shipped.
- [ ] `/favourites` and `/my-recipes` routes still land as empty stub pages
      under the shared layout (unchanged from the original `CFE-006` scope),
      each ready for `CFE-007`/`CFE-008` to fill using this ticket's shared
      mobile-row/empty-state components.

## Non-goals

- Planner (`CFE-012`) — `yp2.png`/`yp6.png` are untouched by this ticket;
  no changes to planner scope or its PREMIUM-badge treatment.
- The Regenerate button itself — blocked on `CROC-052`, a separate backend
  ticket with its own grill.
- Any new backend work beyond `CROC-052`; everything else in this ticket is
  buildable against already-shipped endpoints (`CROC-012`, `CROC-019`,
  `CROC-021`, `CROC-022`, `CROC-049`).
- Retrofitting the mobile overlay/undo pattern onto desktop's existing
  `RecipeCard` cart+stepper (`CFE-020`) — permanently out of scope for that
  component, not deferred.
- Full `CFE-007`/`CFE-008` builds — this ticket only lands their empty
  stub routes; the shared components it introduces are what those tickets
  will build against.

## Verification modes

- **Logic with assertable behaviour** — Vitest (`npm run test` /
  `vitest run`), failing-test-first: the mobile row's overlay/edit state
  machine, the undo auto-dismiss timer, the catalog-search-and-select state
  behind add-extra, `useBoundedServes` reuse for the stepper bounds (1–50).
- **API boundary** — real requests against `crockpot-go` running locally
  (shopping-list add/remove/quantity-edit/obtain-toggle, `GET`/`POST
  /items`, menu add/remove/clear) — founder-run (`npm run dev` +
  `crockpot-go` locally), not self-verified by driving a dev server.
- **Anything visual** — founder's own screenshot comparison against
  `yp1/yp3/yp5/yp7/yp8/yp9/yp10`, both breakpoints.
- **Anything interactive** — hands-on: tap-to-overlay → remove → undo-banner
  flow, add-extra combobox + admin inline item-create dialog, both
  empty-state CTAs.
- **Limits/thresholds** — undo auto-dismiss timing, serves stepper bounds,
  catalog search behaviour — judged through the real client.
