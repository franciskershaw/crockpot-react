## Summary

Build the logged-out landing page at `/` per the 5 PNGs — header, hero,
"Three steps, one list", planner tease, "Pick a plan", footer, plus a
mobile bottom nav — as static presentational markup. Replace
`SignInPlaceholder` with it. Add a public `/recipes` "coming soon" stub
that absorbs the browse/planner nav targets. Land the Crockpot colour
palette and the Newsreader + Karla fonts as design tokens. Every
call-to-action either fires the Google redirect, routes to `/recipes`,
or smooth-scrolls to a section on the same page.

## Decisions and why

### Palette — lands in `src/index.css`, `:root` only, no dark mode

Source of truth: **Claude Design's own palette output** for these
designs (the tool that generated them). Not eyedropped. Light mode only
— the reskin has zero dark screenshots, CFE-001 already stripped
`next-themes` from `sonner`, and a second palette doubles the work for
nothing. Revisit only if a dark design appears.

Base colours → token mapping (convert hex to OKLCH to match the file's
existing style):

| Token | Colour | Role |
| --- | --- | --- |
| `--background` | `#FBF7EF` warm cream | page background |
| `--foreground` | `#23201B` charcoal | body text |
| `--card` / `--popover` | `#FFFCF6` | cards, slightly lighter than bg |
| `--card-foreground` / `--popover-foreground` | `#23201B` | |
| `--primary` | `#3E5A33` sage green | buttons, focus ring |
| `--primary-foreground` | `#FBF7EF` | button label |
| `--secondary` / `--muted` | `#EAE4D6` tan | pill backgrounds, dividers |
| `--secondary-foreground` | `#23201B` | |
| `--muted-foreground` | `#6B6353` taupe | secondary text ("30 mins · serves 4", labels) |
| `--accent` / `--accent-foreground` | `#EAE4D6` / `#23201B` | leave neutral — do **not** make this orange |
| `--border` / `--input` | `#E0D4BB` | subtle tan hairlines |
| `--ring` | `#3E5A33` | green focus outline |
| `--destructive` / `--destructive-foreground` | keep current red | error toasts need real danger-red; `#C0552B` is not it |

Custom decorative tokens (also in `@theme inline` as `--color-*` so
they're usable as utilities later):

| Token | Colour | Role |
| --- | --- | --- |
| `--accent-rust` | `#C0552B` burnt orange | "Three steps" card 01 top border; decorative only, never an interactive colour |
| `--accent-gold` | `#E8C56B` soft gold | "Three steps" card 03 top border |
| card 02 top border | reuse `--primary` | |

The charcoal footer surface reuses `--foreground` as a background; no
separate token.

**Open item for the first visual check:** Claude Design's notes assign
the tan `#EAE4D6` to "page background" and cream `#FBF7EF` to "cards".
The screenshots read lighter than a tan, so the table above uses
cream-bg / lighter-card. If cards don't separate from the background on
the running page, swap `--background` to `#EAE4D6` and `--card` stays
`#FBF7EF`.

### Fonts — Google Fonts `<link>` in `index.html`, serif display + sans body

Serif headline / sans body pairing (confirmed against Claude Design's
font spec, 2026-08-28 — an earlier grill note guessed Fraunces +
Newsreader from the screenshots and was wrong):

- **Newsreader** — `opsz 6..72`, `wght 400;500;600` — display headings
  (the hero headline is 500 weight)
- **Karla** — `wght 400;500;700` — body and everything else (nav, cards,
  pricing, buttons)

`index.html` gets two `<link rel="preconnect">` (fonts.googleapis.com,
fonts.gstatic.com crossorigin) + one stylesheet `<link>` with
`display=swap`.

`src/index.css` `@theme`:

```
--font-display: "Newsreader", Georgia, "Times New Roman", serif;
--font-sans:    "Karla", system-ui, -apple-system, "Segoe UI", sans-serif;
```

Headings use a `font-display` utility; everything else inherits Karla.

**Rejected:** self-hosting via `@fontsource-variable/*`. The correct
perf/privacy answer, but adds deps + import wiring for a pre-launch SPA
with no SSR and no perf budget; the old Next.js app used
`next/font/google`, same posture. Revisit at the Astro migration (Astro
has first-class font handling) or when perf becomes real.

### Nav components are shared-from-the-start; only the footer is landing-local

The old `crockpot` app had one `Navbar` and one `BottomMobileNav`, each
branching on auth state (`isAuthenticated ? appLinks : "Browse Recipes
/ Login"`) and mounted app-wide. `loggedOutUserNav.png`'s name says the
same — one nav with a logged-out *state*. So the nav components are
built as the real shared ones now, with only the logged-out content
this ticket needs:

- `src/components/nav/SiteHeader.tsx` — marketing header (Recipes / How
  it works / Pricing / Sign in). CFE-006 adds the `useAuth` branch (app
  links + user menu) and hoists it into the `AppShell` layout route.
- `src/components/nav/MobileTabBar.tsx` — logged-out tabs (Browse
  Recipes / Login). CFE-006 adds the authed branch.
- `src/components/Logo.tsx` — wordmark, shared by header, footer, and
  the future authed nav.

Building `Landing`-prefixed versions would guarantee a rename in CFE-006
and risk two parallel nav bars.

`src/features/landing/LandingFooter.tsx` **stays landing-local** — the
old app has no footer anywhere; this one is genuinely landing-only.

Still **not** building `AppShell` / layout route / `<Outlet>` — that's
CFE-006. `LandingPage` mounts `<SiteHeader />` + `<MobileTabBar />`
directly for now.

### Mobile bottom nav is in scope

`loggedOutUserNav.png` shows a fixed bottom bar (magnifier "Browse
Recipes" + arrow "Login") on the mobile landing. Build it landing-local,
shown `< md`. Deferring it leaves the mobile pages visibly short of
`lp2.x`.

### `/recipes` stub is public

The landing links to `/recipes` from a logged-out state, so the stub
renders without `RequireAuth` — a plain centred "coming soon". Absorbs
the browse and planner nav targets until CFE-004. Catch-all `*` still
redirects to `/`.

### Logged-in `/` keeps redirecting to `/menu`

`AppRoutes` already sends an authenticated visitor from `/` to
`DEFAULT_AUTHENTICATED_ROUTE`. The marketing page is logged-out only
(the only state the screenshots show). Unchanged.

### "Three steps" — mobile carousel, a deliberate divergence from the mockup

The mockup stacks the three step cards vertically on mobile (`lp2.1`
implies it). That's ~1.5 screens of scroll for an explainer section.
Instead, mobile (`< md`) shows a **manual swipe carousel** — one card
with a peek of the next, dot indicators, driven by shadcn's `Carousel`
(Embla). **No auto-advance** — auto-rotating carousels bury slides 2–3,
fight self-paced reading of sequential (01→02→03) content, and need a
`prefers-reduced-motion` escape hatch. Desktop keeps the mockup's
3-column grid. The step card is one shared component
(`StepCard.tsx`) rendered in both.

Adds `embla-carousel-react` (via `npx shadcn add carousel`; declined
the `button.tsx` overwrite). jsdom needs `ResizeObserver` /
`IntersectionObserver` / `matchMedia` stubs in `setupTests.ts` for any
test that mounts the carousel (e.g. `App.test.tsx`).

### Consistent vertical rhythm between sections

The gap between sections lives on the *top* of the lower section (no
doubled top+bottom padding). `SECTION_GAP` (`styles.ts`) separates
distinct sections; `SUBSECTION_GAP` is the tighter gap for the planner
tease, which reads as part of the "Three steps" story. `<main>` owns the
space before the footer.

### Recipe cards are gray placeholders with generic captions

The hero's 3 overlapping rotated "polaroid" cards (1 on mobile) keep
their layout — white frame, shadow, few-degree rotation — but the photo
area is a flat gray block and the captions are generic ("Recipe name" /
"30 mins · serves 4"), **not** the screenshot's real recipe names, so
nobody reads them as a broken feature. Real cards land in CFE-004.

### CTA wiring

| Control | Action |
| --- | --- |
| "Sign in" (header), "Continue with Google" (hero), "Get started free" (Free card) | `window.location.href = ${import.meta.env.VITE_API_URL}/auth/google/login` |
| "Browse recipes" (hero), "Recipes" (nav + footer), mobile "Browse Recipes" | `<Link to="/recipes">` |
| "How it works", "Pricing" (nav), "Pricing" (footer), "See the planner" | same-page smooth-scroll anchor (`#how-it-works`, `#pricing`; "See the planner" → `#pricing`) |
| Premium / Pro "Coming soon" | disabled `<Button>`, no handler |
| "Privacy", "Contact" (footer) | inert link-styled text — no such pages yet |
| mobile "Login" (bottom nav) | Google redirect |

### Static content

"189 recipes · free forever tier · no card" (mobile: "189 recipes ·
free forever"), "Browse 189 recipes…", all pricing figures and feature
lists — hardcoded strings. No API call for a live recipe count.

## Non-goals

- Dark mode. No design, `sonner` has no theme wiring.
- A shared `AppShell` / authed nav / layout route — CFE-006.
- Real `/recipes`, `/pricing`, `/privacy`, `/contact` pages — later
  tickets; footer links to the last two are inert for now.
- `useDocumentTitle` / per-route titles — first real authed screen.
- Favicon swap to the chef-hat mark — flagged, not done here.
- Live recipe count from the API — `189` is hardcoded.
- Any email/password auth surface — CFE-002b.
- Unit tests for the page — presentational; see Verification.
- A full design-token / typography-scale system beyond what the landing
  needs — extend per-ticket as real screens arrive.
