# CFE-010 — Manual recipe form (create + edit)

The "fill it in yourself" half of `screenshots/add recipe/`: create at
`/recipes/new`, edit at `/recipes/:id/edit`, with a browser-only
autosaved draft and a leave-with-unsaved-changes prompt. Grilled
2026-09-28. Depth: mostly cheap to undo (a screen), except the form's
value shape, which `CFE-011` (ingredient paste), `CFE-013` (link import)
and `crockpot-go` `CROC-039` ("New" items) will all fill. AI-driven;
founder reviews on screen at each piece.

## Facts checked before deciding

- Request body (`crockpot-go/internal/handler/recipe_requests.go:13-34`):
  `name` 3–100, `description` optional ≤500, `timeInMinutes` 1–1440,
  `serves` 1–50 (`validation.go:67`), `instructions` 1–50 non-blank,
  `notes` `string[]` ≤10 (blanks dropped), `categoryIds` 1–3 no dupes,
  `ingredients` 1–50, no duplicate item, quantity > 0, unit optional,
  `image` optional and `https://res.cloudinary.com` only (`:329`).
  `PATCH /recipes/:id` is a full replace with the same body (`CROC-016`).
- Units (`crockpot-go/internal/repository/recipe.go:522-532`): no unit is
  always accepted; a unit must be in the item's allowed set when that set
  is non-empty; an empty set accepts any unit. Quantity column is
  `NUMERIC(10, 2)`; `shopping-list/utils/quantity.ts` already holds the
  6-digit/2-decimal input rule (`CFE-042`).
- `POST /items` is admin-only (`crockpot-go/main.go:160`);
  `AddExtraItem.tsx:34` gates `CreateItemDialog` on `role === "ADMIN"`.
  `AddItemSearch` (cmdk) takes an optional `onCreate`.
- `App.tsx:14` mounts a plain `<BrowserRouter>`; `useBlocker` requires a
  data router. No `useBlocker`/`beforeunload` anywhere yet.
- `AddRecipeLink` is an inert `<span>`; `RecipeEditButton` already links
  to `/recipes/:id/edit`, which has no route.
- Old app steps (`~/projects/crockpot/src/app/recipes/new/components/Instructions.tsx`):
  single-line input, Enter appends a step and focuses it, "Add Step"
  button, trash disabled at one step, blank steps filtered at submit
  (`CreateRecipeForm.tsx:98-100`). Notes: one note per textarea line
  (`recipe-form-helpers.ts` `transformTextareaToNotes`, joined with `\n`).
- `canManageRecipe` (`recipes/hooks/useRecipePermissions.ts:7`): ADMIN or
  creator. `useDeleteRecipe.ts:31-38` is the list/favourites cache
  precedent.

## Decisions

1. **Drafts are browser-only.** One `localStorage` draft for the create
   form, autosaved as you type, restored on return to `/recipes/new`,
   cleared on successful create. "Draft saved" indicator stays; the
   "Save as draft" button is dropped (no distinct job once autosave
   exists, and it would imply a server save). Edit mode does not
   autosave. Rejected: server drafts (schema change, relaxed validation,
   cap/`mine`/approval ripple for two admin users). Revisit if cross-
   device drafts are asked for.
2. **Leave prompt via a data router.** Migrate `App.tsx` to
   `createBrowserRouter([{ path: "*", element: … }])` with `AppRoutes`'
   `<Routes>` unchanged underneath, on its own first commit. The form
   blocks with `useBlocker` (in-app links, back/forward, iOS swipe-back)
   and `beforeunload` (reload/close), only while dirty and never after a
   successful save; the dialog is `ConfirmActionDialog`. Known limits:
   iOS plays the swipe animation before the block restores the page;
   swiping out of the site from a first-in-history edit page can't be
   blocked (create is covered by the draft). `ScrollToTop` unchanged.
3. **Form value shape** — one `RecipeFormValues` with `fromDetail`
   (`RecipeDetail` → values) and `toRequest` (values → body). Paste and
   import will produce `RecipeFormValues` into the same form.
   ```ts
   type IngredientRow = { key: string; itemId: string; itemName: string;
                          unitId: string | null; quantity: string };
   type RecipeFormValues = {
     name: string; image: { url: string; filename: string } | null;
     description: string | null; timeInMinutes: number; serves: number;
     categoryIds: string[]; ingredients: IngredientRow[];
     instructions: { key: string; text: string }[]; notes: string;
   };
   ```
   `itemId` is required: nothing in this ticket produces an unmatched
   row, and widening it for `CROC-039` is compiler-guided. `quantity`
   stays a string until `toRequest`, parsed with the shopping-list rule,
   which moves to shared `lib/` (second caller).
4. **Units** offered = the item's allowed set if non-empty, else all
   units, plus "–" (none). Mirrors the backend so
   `unit_not_allowed_for_item` is unreachable.
5. **Duplicates**: picking an already-listed item focuses its row
   instead of adding one. Rejected: merging quantities (silently changes
   a value).
6. **Notes**: one textarea, one note per non-blank line (the old app's
   rule, lossless for migrated data); edit joins with `\n`. More than 10
   non-blank lines is a form error.
7. **Description**: not in the design, not in the form. Carried through
   `fromDetail` → `toRequest` unchanged so `PATCH` doesn't wipe it.
8. **No reordering** of ingredients or steps; no drag handles. New
   ingredient rows append.
9. **Steps** port the old app with two changes: Enter inserts a step
   *after* the current one (the only way to place a forgotten step
   without reordering) and focuses it; a multi-line paste splits on
   newlines, strips leading numbering ("1.", "1)", "Step 1:"), drops
   blank lines, fills the current step and inserts the rest after it.
   Steps are auto-growing textareas where Enter never inserts a newline.
   "Add step" appends. Trash per step, hidden when only one. Blank steps
   are dropped at save, never an error on their own.
10. **Ingredients section**: search (`AddItemSearch`) shown directly, not
    behind the "search instead" link; empty state "No ingredients yet —
    search our list below." Admins get "Create 'X'" via
    `CreateItemDialog`, as the shopping list does. No paste box
    (`CFE-011`), no matched dots or "New" badges (`CROC-039`).
11. **Routes**: `/recipes/new` and `/recipes/:id/edit`, both under
    `RequireAuth`, lazy. `AddRecipeLink` becomes a `<Link>` to
    `/recipes/new`. Edit loads via `getRecipe`/`recipeKeys.detail`; if
    `canManageRecipe` is false, redirect to `/recipes/:id`.
12. **After save**: `navigate("/recipes/:id", { replace: true })`; seed
    `recipeKeys.detail` with the response; invalidate `recipeKeys.lists()`
    and `recipeKeys.favourites()`; on edit also invalidate the menu and
    shopping list. Non-admin create: toast "Submitted — only you can see
    it until it's approved." Non-admin editing an approved recipe: footer
    note "Saving sends this back for approval." `409
    recipe_limit_reached`: footer error, draft kept. No pre-flight cap
    check.
13. **Validation**: Zod mirrors the backend limits above. Footer shows
    live status — the missing items in `ar1`'s wording, or `ar3.1`'s
    "Looks complete — ready to publish". Publish is never disabled;
    submitting with gaps shows inline errors (first attempt onward) and
    focuses the first. Any server 400 shows as one generic footer error.
    Labels: "Publish recipe" (create), "Save changes" (edit).
14. **Steppers**: time defaults 30, ±5, clamped 1–1440, typeable; serves
    defaults 4, ±1, 1–50.
15. **Photo**: omitted on create until `crockpot-go` `CROC-040`. On edit
    an existing image shows read-only and is sent back unchanged.
16. **Undesigned states** (no screenshot): edit mode reuses the create
    layout titled "Edit recipe" with no import card; field errors use the
    existing destructive text style under each section; leave prompt is
    `ConfirmActionDialog` as-is. Mobile header per `ar4.0` (back arrow
    goes through the leave prompt).

## Visual acceptance (from `screenshots/add recipe/`)

- `ar1`/`ar4.0`: page title + subtitle, "Draft saved" indicator top
  right; two-column desktop layout — details card (name, cooking time
  and serves steppers, category pills "pick 1–3") left, Ingredients and
  Instructions cards right; single column on mobile with back-arrow
  header. Import card is not rendered (`CFE-013`).
- `ar3.0`: ingredient rows as quantity input, unit select, item name,
  trash — without drag handles or status dots; count badge beside the
  "Ingredients" heading; numbered step circles with trash per step.
- `ar3.1`: "Chef's notes" card revealed by "+ Add chef's notes
  (optional)", with trash to remove it.
- `ar1`/`ar4.1`: sticky footer bar with status text left, single
  primary button right (no "Save as draft"); stacked on mobile.
- Styling from the Claude-Design spec dump the founder supplies at
  piece 2 — no markup before it.

## Acceptance criteria

- [ ] App runs under `createBrowserRouter`; every existing route,
      redirect, back/forward and scroll-to-top behaves as before.
- [ ] Header, mobile tab bar and My recipes empty state link to
      `/recipes/new`; `RecipeEditButton` reaches a working edit page.
- [ ] A non-owner, non-admin hitting `/recipes/:id/edit` lands on
      `/recipes/:id`.
- [ ] Enter/paste/add/trash step behaviour per decision 9.
- [ ] Unit options, duplicate handling and admin item creation per
      decisions 4, 5, 10.
- [ ] Footer status and submit-time errors per decision 13.
- [ ] Create saves against the real API, lands on the detail page with
      no spinner, and appears in My recipes; non-admin sees the pending
      toast.
- [ ] Editing a migrated recipe preserves its image, description and
      every note line; menu and shopping list refresh.
- [ ] Create draft survives a reload and clears after a successful save.
- [ ] Dirty form prompts on in-app navigation, back/swipe-back and
      reload; clean or just-saved form never prompts.
- [ ] `npm run build` chunk check: the form's deps stay out of the eager
      bundle (`LESSONS.md` 2026-09-27).

## Pieces and verification

Each piece is one commit; stop at each for the founder's look.

1. **Data-router migration** — existing Vitest suite green; founder
   clicks through every route incl. back/forward and scroll. (interactive)
2. **Thin slice of `/recipes/new`** — details card, steps, notes, footer
   status; no submit. Failing tests first for the method-split helper and
   footer missing-fields logic; founder compares against `ar1`, `ar3.1`,
   `ar4.0`, `ar4.1` and tries Enter/paste. (logic + visual + interactive)
3. **Ingredients section** — failing tests first for unit options and
   duplicate handling; founder compares against `ar3.0`. (logic + visual)
4. **Create submit** — failing tests first for the Zod schema,
   `toRequest`, and the post-save cache hook; founder creates a real
   recipe against local `crockpot-go`. (logic + API boundary)
5. **Edit mode** — failing round-trip test (`fromDetail` → `toRequest`
   lossless for a migrated recipe with multi-line notes, image,
   description); founder edits a real migrated recipe. (logic + API)
6. **Autosave + leave prompt** — failing tests for draft save/restore;
   founder tries reload, in-app links, the logo, and swipe-back on a
   phone. (logic + interactive)

## Non-goals

- Photo upload (`crockpot-go` `CROC-040`).
- Ingredient paste box / parser (`CFE-011`) and link import (`CFE-013`).
- Unmatched/"New" ingredient rows (`crockpot-go` `CROC-039`).
- Server-side drafts; edit-mode autosave.
- Reordering ingredients or steps.
- A description field.
